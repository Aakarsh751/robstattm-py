# Documentation Plan — port from CRAN R man pages

**Status:** plan finalized 2026-06-11. Locked by decision **D-017**.
**Next action (locked, user-approved 2026-06-11):** execute **M1 + M2** in
a single session — Rd extractor + 5-wrapper pilot renderer. Resume
prompt for that session is `project_memory/resume_prompts.md` Prompt #6.

The Python package's reference documentation is generated by porting every
`.Rd` man page from CRAN `RobStatTM` into Sphinx-rendered pages, and
fusing them with Python `autodoc` output. R man pages are the source of
truth for *what the function does*; Python autodoc is the source of
truth for *how to call it from Python*.

## 1. Goals

1. **Single source of truth per wrapper page.** Every Python wrapper has
   exactly one rendered HTML page that contains: description, signature
   (Python), arguments (R↔Python mapped), return fields (R list ↔
   Python dataclass), example (side-by-side R + Python), references.
2. **Upstream tracking.** When RobStatTM updates a man page, our docs
   pick up the change automatically on the next `make docs` run.
3. **Zero-handwriting principle.** We do **not** rewrite man-page prose
   ourselves. The R authors maintain it; we render it. Only the
   Python-specific bits (signature, dataclass fields, `to_dict()` /
   `to_r()` / etc.) come from autodoc.
4. **Discoverability.** Users can find a function by either its R name
   or its Python name, online (RTD search), in the IDE (`rpm.help(...)`),
   or in Jupyter (`?rpm.lmrobdet_mm`).
5. **Buildable on push.** GitHub Actions builds and deploys to
   ReadTheDocs (or GitHub Pages) on every commit to `main`.

| Tool | Role | Rationale |
|---|---|---|
| **Sphinx** ≥ 7 | Docs engine | De-facto Python standard, RTD-native |
| **MyST-Parser** | Markdown source | Markdown is easier to skim than RST for tabular content like our argument tables |
| **sphinx-design** | Tabbed code blocks, cards | Side-by-side R / Python tabs per example |
| **sphinx-autodoc** | Python signatures + docstrings | Single source for `rpm.<name>(...)` |
| **autodoc-typehints** | Type-hint rendering | Frozen-dataclass return types render cleanly |
| **sphinx-autosummary** | Auto-generated TOC / cross-refs | One line per wrapper in the API page |
| **nbsphinx** | Embed Jupyter notebooks | Tutorials + gallery |
| **furo** theme | Modern, dark-mode, RTD-compatible | Quick wins |
| **R + rpy2** | Reading `.Rd` via `tools::Rd_db()` | Already in dev env |
| **GitHub Actions** | CI build + RTD trigger | Cheap, standard |

## 4. The extraction pipeline

```
                ┌────────────────────────────┐
                │  tools::Rd_db("RobStatTM") │   in R
                └──────────────┬─────────────┘
                               │  57 parsed Rd objects
                               ▼
   ┌────────────────────────────────────────────────────────┐
   │  docs/scripts/extract_rd.R                             │
   │  - walk each Rd, emit a structured JSON record         │
   │    {name, title, description, arguments[], value[],    │
   │     examples_r, seealso[], references, sections{}}     │
   └──────────────┬─────────────────────────────────────────┘
                  │  docs/_rd_json/<RName>.json  (57 files)
                  ▼
   ┌────────────────────────────────────────────────────────┐
   │  docs/scripts/render_rd.py                             │
   │  - read JSON                                           │
   │  - load _help._R_TO_PY name map                        │
   │  - apply renames inside text via regex pass            │
   │    (lmrobdetMM -> lmrobdet_mm, tuning.psi -> tuning_psi)│
   │  - emit docs/wrappers/<py_name>.md (MyST)              │
   │    using the template in §5 below                      │
   └──────────────┬─────────────────────────────────────────┘
                  │  one .md per Python wrapper
                  ▼
   ┌────────────────────────────────────────────────────────┐
   │  Sphinx build (`make html`)                            │
   │  - MyST renders the .md                                │
   │  - autodoc injects Python signatures + dataclass docs  │
   │  - nbsphinx renders tutorials                          │
   │  - cross-refs resolve via intersphinx + the name map   │
   └────────────────────────────────────────────────────────┘
                               │
                               ▼
                       docs/_build/html/
```

Both scripts are idempotent — running them again with no Rd changes
produces a no-op `git diff`.

## 5. Per-wrapper page template (MyST)

Saved as `docs/templates/wrapper_page.md.jinja`:

````markdown
# `{{ py_name }}`  ({{ r_name }})

```{eval-rst}
.. currentmodule:: robstattm_py
.. autofunction:: {{ py_name }}
```

## Description

{{ rd.description | py_renamed }}

## Parameters

| Python name | R name | Type | Description |
|---|---|---|---|
{% for arg in rd.arguments %}
| `{{ arg.py_name }}` | `{{ arg.r_name }}` | _{{ arg.type }}_ | {{ arg.description | py_renamed }} |
{% endfor %}

## Returns

`{{ py_result_class }}` — a frozen dataclass. Fields:

| Python attribute | R list field | Description |
|---|---|---|
{% for field in rd.value %}
| `.{{ field.py_name }}` | `${{ field.r_name }}` | {{ field.description | py_renamed }} |
{% endfor %}

## Example

::::{tab-set}
:::{tab-item} Python
```python
{{ python_example }}
```
:::
:::{tab-item} R
```r
{{ rd.examples_r }}
```
:::
::::

{% if rd.details %}
## Notes

{{ rd.details | py_renamed }}
{% endif %}

{% if rd.sections %}
{% for title, body in rd.sections.items() %}
### {{ title }}

{{ body | py_renamed }}
{% endfor %}
{% endif %}

## See also

{% for ref in rd.seealso %}
- {func}`~robstattm_py.{{ ref.py_name }}` ({{ ref.r_name }})
{% endfor %}

## References

{{ rd.references }}

```{eval-rst}
.. note::
   Documentation generated from ``RobStatTM/man/{{ r_name }}.Rd``
   (CRAN version |robstattm_version|).
```
````

The `py_renamed` Jinja filter applies the R↔Python name map to every
referenced symbol in prose (e.g. "see `lmrobdetMM`" → "see
`lmrobdet_mm`").

## 7. Cross-cutting features

### 7.1 Bilingual search index
Sphinx's search ingests both the Python identifier and the R original
name (we add the R name as a hidden Sphinx index entry via a custom
extension or via `.. index::` directives at the top of each page).
Result: searching "lmrobdetMM" finds the same page as "lmrobdet_mm".

### 7.2 R-name aliases in autosummary
`api/index.md` shows a single sortable table:

| Python | R | Module | Strict-tier tested |
|---|---|---|---|
| `lmrobdet_mm` | `lmrobdetMM` | `regression` | ✅ |
| ... | ... | ... | ... |

Auto-generated from `_help._R_TO_PY` + the test runner.

### 7.3 Cross-version pinning
Each wrapper page footer prints the RobStatTM version used to extract
the man page. CI fails if the installed `RobStatTM` version is older
than the version declared in `pyproject.toml` extras.

### 7.4 Example fidelity check
Every embedded Python example in the rendered docs is **executed** at
build time (via `doctest` or `sphinx-doctest`) — broken examples fail
the build.

### 7.5 Side-by-side R↔Python translator
A small JS widget on every wrapper page: paste an R call, see the
Python equivalent. Powered by the name map + a tiny formula-string
inspector. Stretch goal; defer to v0.2.

## 8. Build / CI / hosting

1. **GitHub Actions workflow** (`.github/workflows/docs.yml`):
   - Trigger: push to `main`, manual dispatch, weekly schedule (to catch
     a new RobStatTM release).
   - Steps: checkout → install R + RobStatTM + python deps → run
     extractor → run renderer → `sphinx-build -W` (warnings = errors)
     → upload artifact.
2. **ReadTheDocs**: standard YAML config, builds on every push, hosts
   on `robstattm-py.readthedocs.io`. Falls back to GH Pages if RTD
   integration is delayed.
3. **PR previews** via RTD's PR-builder so reviewers see rendered docs
   inline with code review.

## 11. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Rd LaTeX-flavored markup (`\eqn{...}`, `\code{}`) needs custom rendering | High | Use `tools::Rd2HTML` for the partial conversion of math + inline code; post-process in the renderer |
| Name remapping inside prose creates false positives (e.g. "MM" as a phrase, not a function) | Medium | Renames only fire when the source is wrapped in `\code{}` or `\link{}`, never in free text |
| Embedded R examples (`\examples`) may rely on extra packages | Low | The pipeline records dependencies in the JSON; CI installs them |
| RTD build timeout from R installation | Medium | Pre-built R binaries via apt; fall back to GH Pages if needed |
| nbsphinx execution slow for cov_rob_mm in tutorial 02 | Low | Cache executed notebooks (`nbsphinx_execute = 'auto'`) |

## 12. What this plan deliberately defers

- **Translated narrative.** We render the R authors' prose verbatim
  (with symbol-only renames). A future v0.2 may add a "Python translator
  note" sidebar per page; not v0.1.
- **PDF / EPUB builds.** HTML-only for v0.1.
- **Localization.** English only.
- **Interactive R-to-Python translator widget** (§7.5 above). Stretch.
